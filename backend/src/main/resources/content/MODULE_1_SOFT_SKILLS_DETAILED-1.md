### LESSON 1.1: Структура Self-Introduction (20 хвилин)

#### Теоретична частина:

**3 рівні самопрезентації:**

**Level 1 - Quick intro (15-30 seconds):**
```
"Hi, I'm [Name]. I'm a [Position] at [Company]."
```

**Level 2 - Professional intro (30-60 seconds):**
```
"Hi, I'm [Name]. I'm a [Position] at [Company]. 
I specialize in [Area] and I've been working with [Technologies] 
for about [Time period]."
```

**Level 3 - Extended intro (60-90 seconds):**
```
"Hi, I'm [Name]. I'm a [Position] at [Company], where I [main responsibility].
I specialize in [Area] and I've been working with [Technologies] 
for about [Time period]. Before this, I [previous experience].
I'm particularly interested in [interest/passion]."
```

#### Аналіз компонентів:

**1. Name introduction (Ім'я):**
- ❌ Типова помилка: "My name is Oleksandr" (занадто формально)
- ✅ Краще: "Hi, I'm Oleksandr" or "I'm Alex" (дружнє, природне)
- ✅ З поясненням: "I'm Oleksandr, but most people call me Alex"

**2. Position/Role (Посада):**
- ❌ Занадто складно: "I'm a Senior Full-Stack Software Development Engineer"
- ✅ Просто і ясно: "I'm a software developer" / "I'm a backend engineer"
- ✅ З контекстом: "I'm a backend developer focusing on APIs"

**3. Company mention (Компанія):**
- ✅ Якщо відома: "I work at Google" 
- ✅ Якщо невідома: "I work at TechStartup, a fintech company in Kyiv"
- ✅ Якщо freelance: "I'm a freelance developer" / "I work independently"

**4. Specialization (Спеціалізація):**
- ✅ "I specialize in backend development"
- ✅ "I focus on building scalable APIs"
- ✅ "I work mainly with microservices architecture"

**5. Experience timeline (Досвід):**
- ✅ "I've been doing this for about 3 years"
- ✅ "I've been working with Python for 5 years"
- ❌ Уникайте: "I have 3 years and 7 months of experience" (занадто точно)

### LESSON 1.2: Grammar Focus - Present Perfect vs Present Simple (25 хвилин)

#### Чому це критично для IT?

В IT постійно треба говорити про досвід. І тут є чітке правило:

**Present Simple** = щось, що ви робите зараз, регулярно, як частина вашої роботи
**Present Perfect** = ваш досвід, що почався в минулому і продовжується досі

#### Правило 1: Описуємо поточну роботу - Present Simple

```
✅ "I work at Google" (Я працюю в Google - зараз)
✅ "I develop backend services" (Я розробляю backend сервіси - моя робота)
✅ "I write Python code every day" (Я пишу Python код щодня - регулярно)
```

#### Правило 2: Описуємо досвід - Present Perfect

```
✅ "I've worked in IT for 5 years" (Маю 5 років досвіду, продовжую працювати)
✅ "I've been using Java since 2020" (Використовую з 2020, досі використовую)
✅ "I've developed over 20 APIs" (Розробив понад 20 API за кар'єру)
```

#### Сигнальні слова:

**For + період часу** → Present Perfect
- "I've worked here **for** 3 years"
- "I've been coding **for** a decade"

**Since + конкретний момент** → Present Perfect
- "I've been with this company **since** 2021"
- "I've been using React **since** version 16"

**Every day / usually / always** → Present Simple
- "I **write** tests **every day**"
- "I **usually** work with microservices"

### LESSON 1.3: Creating Your Elevator Pitch (15 хвилин)

#### Що таке Elevator Pitch?

Це ваша 30-60 секундна самопрезентація, яку ви можете сказати:
- На networking event
- На початку співбесіди
- Коли хтось питає "What do you do?"
- При знайомстві з новою командою

#### Структура (The Formula):

```
[Name] + [Role] + [Company/Context] + [Specialization] + [Interesting Detail]
```

#### Приклади elevator pitches:

**Example 1 - Junior Developer:**
```
"Hi, I'm Andriy. I'm a junior backend developer at SoftServe. 
I work mainly with Python and Django, building APIs for e-commerce platforms. 
I've been coding for about 2 years, and I'm really excited about 
learning more about microservices architecture."
```

**Розбір:**
- Name: Andriy ✓
- Role: junior backend developer ✓
- Company: SoftServe ✓
- Specialization: Python, Django, APIs ✓
- Interesting detail: excited about microservices ✓
- Час: ~15 секунд ✓

**Example 2 - Mid-level Developer:**
```
"Hi, I'm Kateryna, but everyone calls me Kate. I'm a full-stack developer 
working remotely for a US-based fintech startup. I specialize in React 
on the frontend and Node.js on the backend. I've been doing this for about 
5 years now. What I love most about my work is solving complex problems 
and seeing the direct impact on users."
```

**Розбір:**
- Name + nickname: Kateryna/Kate ✓
- Role: full-stack developer ✓
- Company context: US fintech startup, remote ✓
- Specialization: React + Node.js ✓
- Interesting detail: loves problem-solving & user impact ✓
- Час: ~20 секунд ✓

**Example 3 - Senior Developer:**
```
"I'm Oleksandr, a senior backend engineer at Grammarly. I've been with 
the company for 3 years, working on the core API that powers our writing 
suggestions. Before that, I spent 5 years in e-commerce, building 
high-traffic payment systems. I'm particularly passionate about system 
design and scalability challenges. These days, I'm also mentoring junior 
developers on the team."
```

**Розбір:**
- Name: Oleksandr ✓
- Role + seniority: senior backend engineer ✓
- Company: Grammarly ✓
- Current work: core API ✓
- Previous experience: e-commerce, payments ✓
- Passion: system design, scalability ✓
- Extra: mentoring ✓
- Час: ~25 секунд ✓

### LESSON 2.2: Grammar Focus - Present Continuous for Current Projects (20 хвилин)

#### Коли використовувати Present Continuous в IT?

**Present Continuous** = щось, що відбувається ЗАРАЗ, в цей період вашого життя/роботи

Це ідеально для опису:
- Поточних проєктів
- Того, над чим ви працюєте цього тижня/місяця
- Тимчасових завдань
- Того, що ви вивчаєте зараз

#### Формула:
```
I am (I'm) + VERB-ing
We are (We're) + VERB-ing
The team is + VERB-ing
```

#### Коли використовувати в IT контексті:

**1. Current projects:**
```
✅ "I'm working on a new authentication service"
✅ "We're building a dashboard for analytics"
✅ "The team is developing a mobile app"
```

**2. Temporary tasks:**
```
✅ "I'm fixing some critical bugs this week"
✅ "I'm helping the frontend team with API integration"
✅ "I'm reviewing code for the new feature"
```

**3. Learning/Development:**
```
✅ "I'm learning Kubernetes right now"
✅ "I'm currently exploring AI/ML technologies"
✅ "I'm taking a course on system design"
```

**4. Ongoing initiatives:**
```
✅ "We're migrating from monolith to microservices"
✅ "The company is expanding to European markets"
✅ "I'm transitioning to a tech lead role"
```

#### Present Continuous vs Present Simple - Side by side:

| Present Simple (Regular/Permanent) | Present Continuous (Now/Temporary) |
|-----------------------------------|-----------------------------------|
| I work with Python | I'm working on a Python project |
| I develop APIs | I'm developing a new API |
| We use React | We're using React for this project |
| I write tests | I'm writing tests for the new feature |
| The app serves users | The app is growing rapidly |

### LESSON 2.3: Variations of Your Introduction (15 хвилин)

#### Чому потрібні варіації?

Різні ситуації вимагають різного рівня деталізації:
- **Networking event** - короткий і engaging
- **Job interview** - детальний і professional
- **Casual meeting** - дружній і conversational
- **Conference** - з акцентом на expertise

#### Version 1: Ultra-Short (10-15 seconds)

**Коли використовувати:** швидке знайомство, перші секунди розмови

```
"Hi, I'm [Name]. I'm a [Role] working with [Main Tech/Area]."

Examples:
- "Hi, I'm Max. I'm a backend developer working with Python."
- "I'm Anna. I'm a frontend engineer working mainly with React."
- "I'm Sergiy, DevOps engineer, I work with cloud infrastructure."
```

#### Version 2: Standard (30-45 seconds)

**Коли використовувати:** більшість networking situations

```
"Hi, I'm [Name]. I'm a [Role] at [Company/Context]. 
I [Current work] and I've been [Experience]. 
I'm particularly interested in [Interest]."

Example:
"Hi, I'm Dmytro. I'm a full-stack developer at a startup in Lviv. 
I build web applications using React and Node.js, and I've been 
doing this for about 3 years. I'm particularly interested in 
performance optimization and user experience."
```

#### Version 3: Extended (60-90 seconds)

**Коли використовувати:** початок співбесіди, детальне networking

```
"Hi, I'm [Name]. I'm a [Role] at [Company], where [Responsibility]. 
I specialize in [Specialization] and I've been working with [Technologies] 
for [Time]. Before this, I [Previous experience]. Currently, I'm working on 
[Current project]. What really excites me is [Passion/Interest]."

Example:
"Hi, I'm Yulia. I'm a senior frontend developer at GlobalLogic, where 
I lead a team of 5 developers building a healthcare platform. I specialize 
in React and TypeScript, and I've been working with these technologies for 
about 6 years. Before GlobalLogic, I worked for 3 years in e-commerce, 
building customer-facing applications. Currently, I'm working on implementing 
a real-time video consultation feature for doctors and patients. What really 
excites me is creating applications that directly improve people's lives."
```

### LESSON 3.1: Common Follow-up Questions (25 хвилин)

#### Після вашої презентації, типові питання:

**Group 1: About Your Work**

**Q1: "What do you work on?" / "What are you working on?"**

Good answers:
```
✅ "Right now, I'm working on a payment processing system for an e-commerce platform."
✅ "I'm building APIs for a mobile banking app."
✅ "Currently, I'm developing a dashboard for data analytics."
```

Bad answers:
```
❌ "Different things" (занадто vague)
❌ "Just some backend stuff" (недостатньо інформації)
❌ "It's complicated" (звучить як відмова говорити)
```

**Q2: "What technologies do you use?" / "What's your tech stack?"**

Good answers:
```
✅ "Mainly Python with Django for the backend, and PostgreSQL for the database."
✅ "We use React on the frontend and Node.js with Express on the backend."
✅ "I work with Java Spring Boot, and we're using microservices architecture."
```

**Q3: "How long have you been doing this?"**

Good answers:
```
✅ "I've been a developer for about 4 years."
✅ "I've been working in IT for 6 years, but specifically with Python for 3."
✅ "I've been coding professionally since 2019."
```

**Q4: "What do you enjoy most about your work?"**

```

### LESSON 4.1: Formality Spectrum (25 хвилин)

#### Understanding Formality Levels

В англійській існує spectrum від дуже formal до дуже casual. В IT середовищі, typical level - **business casual**.

```
Very Formal ←------ Business Casual ------→ Very Casual
(Academic)      (IT/Tech - HERE!)         (Friends)
```

#### Level 1: VERY FORMAL (рідко в IT, але знати треба)

**Characteristics:**
- Full sentences, no contractions
- Passive voice
- Complex vocabulary
- No slang

**Example:**
```
"Good morning. My name is Oleksandr Petrenko. I am a software development 
engineer with seven years of experience in enterprise applications. I would 
be delighted to discuss potential collaboration opportunities with your 
organization."
```

**Коли використовувати:**
- Офіційна корреспонденція з executives
- Formal presentations
- Academic contexts
- Grant applications

---

#### Level 2: BUSINESS PROFESSIONAL (іноді в IT)

**Characteristics:**
- Structured sentences
- Some contractions okay
- Professional vocabulary
- Polite and respectful

**Example:**
```
"Good morning, I'm Oleksandr. I'm a software engineer with 7 years of 
experience. I've been working primarily with backend systems and I'd love 
to learn more about your company's technical challenges."
```

**Коли використовувати:**
- Job interviews (initial stages)
- Client meetings
- Conference presentations
- Networking with seniors/executives

---

#### Level 3: BUSINESS CASUAL (найчастіше в IT!)

**Characteristics:**
- Conversational but professional
- Contractions normal
- Mix of professional & everyday words
- Friendly tone

**Example:**
```
"Hey, I'm Sasha. I'm a backend dev with about 7 years under my belt. 
I've mostly worked on APIs and microservices. Would love to hear what 
you're working on!"
```

**Коли використовувати:**
- Team meetings
- Daily standups
- Slack conversations
- Tech meetups
- Peer interviews

---

#### Level 4: CASUAL (з колегами, яких добре знаєте)

**Characteristics:**
- Relaxed language
- Slang okay
- Shortened forms
- Humor & personality

**Example:**
```
"Hey! I'm Sasha, backend guy. Been coding for like 7 years, mostly API stuff. 
Pretty much live in microservices land these days. What about you?"
```

**Коли використовувати:**
- Close colleagues
- After-work hangouts
- Casual team chats
- Online gaming with coworkers

---

### LESSON 4.2: Cultural Differences in IT Communication (25 хвилин)

#### Understanding Communication Styles

Different cultures have different communication norms. As a Ukrainian working in international IT:

#### Direct vs Indirect Communication

**Direct (US, Germany, Netherlands, Israel):**
- Say what you mean clearly
- "No" means no
- Feedback is straightforward
- Disagreement is normal and healthy

**Example (Direct):**
```
"I don't think this approach will work because of X, Y, Z. 
I suggest we do A instead."
```

**Indirect (Asia, some European countries):**
- Soften messages
- Avoid direct "no"
- Feedback is gentler
- Disagreement is subtle

**Example (Indirect):**
```
"This is an interesting approach. Have we considered the challenges 
with X? Perhaps we might want to explore alternative options like A?"
```

**Ukrainian style typically:** Довольно direct, але треба адаптувати

---

#### Small Talk Expectations

**US/UK Style:**
- Small talk before business is expected
- Weather, weekend, sports are safe topics
- Build rapport before diving into work

**Typical flow:**
```
"Hey, how was your weekend?"
"Good, thanks! Went hiking. You?"
"Nice! I just relaxed at home. So, about that API..."
```

**Germanic/Eastern European Style:**
- Less small talk, more direct to business
- But in IT (especially remote), adapting to US style helps

**Pro tip for Ukrainians:**
```
✅ Learn small talk even if it feels странним
✅ Americans see it as politeness, not waste of time
✅ 2-3 minutes of small talk = relationship building
```

---

#### Politeness Levels

**British English:**
- Very indirect and polite
- Many "sorry", "please", "would you mind"
- Questions instead of requests

**Examples:**
```
"Sorry, would you mind sending me that file?"
"Could I possibly ask you to review this when you get a chance?"
"I was wondering if you might be able to help me with something?"
```

**American English:**
- Direct but friendly
- Less formal than British
- More casual contractions

**Examples:**
```
"Could you send me that file?"
"Can you review this when you have time?"
"Could you help me with something?"
```

**How to adapt (as Ukrainian):**
```
✅ Add "please" and "thank you" more than you think necessary
✅ Use "Could you" instead of "Send me"
✅ Soften with "when you get a chance" / "if you have time"
✅ Don't worry about being "too polite" - it's better than too direct
```

---

#### Email/Slack Culture

**Email formality:**

❌ Too formal for most IT contexts:
```
Dear Mr. Johnson,

I am writing to inquire about the status of the pull request 
I submitted on the 15th of January.

Yours faithfully,
Oleksandr Petrenko
```

✅ Good for IT business casual:
```
Hi John,

Hope you're doing well! I wanted to follow up on the PR I submitted 
last week (#1234). Could you take a look when you get a chance?

Thanks!
Sasha
```

**Slack norms:**

✅ Even more casual:
```
"Hey! Quick question - did you get a chance to look at that PR?"
"Thanks! 🙏"
"No worries, take your time!"
```

**Ukrainian adaptation:**
```
✅ It's okay to be friendly and casual in Slack
✅ Emojis are professional in IT context (👍 ✅ 🎉)
✅ "Thanks!" is better than just "OK"
✅ Use GIFs if team culture supports it
```

---

#### Common Cultural Mistakes (and how to avoid them):

**Mistake 1: Being too direct with criticism**

❌ "This code is bad. You should rewrite it."

✅ "I see what you're trying to do here. Have you considered [alternative approach]? 
It might help with [specific benefit]."

---

**Mistake 2: Not enough positive feedback**

In Ukrainian culture: criticism without praise is normal
In US/Western culture: sandwich negative with positive

❌ "Here are 10 things wrong with your code."

✅ "Great work on the logic here! I have a few suggestions for improvement:
[suggestions]. Overall, good job on meeting the deadline!"

---

**Mistake 3: Skipping small talk as "waste of time"**

❌ [Meeting starts]
"Let's begin with the agenda..."

✅ [Meeting starts]
"Hey everyone! How's everyone doing today? Good? Great! 
Alright, let's dive into the agenda..."

---

**Mistake 4: "No" without softening**

❌ "No, I can't do that."

✅ "Unfortunately, I won't be able to take that on right now due to X. 
However, I could help with Y, or we could revisit this next week?"

---

**Mistake 5: Not asking clarifying questions**

Ukrainian tendency: figure it out yourself, don't bother people
Western IT culture: questions are encouraged

❌ [Confused about task, starts working anyway]

✅ "Just to make sure I understand correctly: you want me to [repeat understanding], 
right? And the deadline is [date]?"

### LESSON 5.2: Writing vs Speaking - Key Differences (20 хвилин)

#### Speaking vs Writing in Professional Context:

| Aspect | Speaking | Writing |
|--------|----------|---------|
| **Structure** | Can be loose, conversational | Should be tighter, organized |
| **Repetition** | Okay to repeat for emphasis | Avoid repetition |
| **Contractions** | Always use (I'm, you're, it's) | Usually okay in LinkedIn |
| **Sentence length** | Shorter, punchier | Can be longer, more complex |
| **Pauses** | Natural pauses, "um", "like" | No filler words |
| **Corrections** | Can rephrase mid-sentence | Edit before publishing |
| **Tone markers** | Voice, intonation, facial expression | Punctuation, word choice |

#### Example Comparison:

**Speaking (Elevator Pitch):**
```
"Hi, I'm Alex. So, I'm a backend developer, um, and I've been working with,

```

**Writing (LinkedIn About):**

```
(Polished, no hesitations, more formal vocabulary)

#### Spoken Language Features (okay when speaking, not writing):

**Fillers:**
- "um", "uh", "like", "you know", "so", "basically", "actually"

**Hedging:**
- "kind of", "sort of", "pretty much", "I guess", "I think"

**False starts:**
- "I was... Actually, let me rephrase that..."
- "The main thing is... Well, one of the main things..."

**Casual connectors:**
- "So anyway...", "But yeah...", "And like..."

---

#### Written Language Features (use in LinkedIn, emails, docs):

**Stronger verbs:**
- Instead of: "I work with APIs"
- Write: "I design and implement RESTful APIs"

**Specific numbers:**
- Instead of: "many users"
- Write: "100,000+ active users"

**Active voice (usually):**
- Instead of: "The system was built by me"
- Write: "I built the system"

**Professional vocabulary:**
- Instead of: "I'm really good at coding"
- Write: "I'm proficient in full-stack development"

### LESSON 6.2: Office/Remote Etiquette (20 хвилин)

#### Communication Etiquette - First Week:

**DO's:**

✅ **Be early** (5-10 minutes before meetings)
```
"Hi! I'm here a bit early – better than being late on my first week!"
```

✅ **Ask questions** (shows engagement)
```
"Just to make sure I understand correctly – you want me to...?"
```

✅ **Take notes** (shows you're paying attention)
```
"Let me write that down so I don't forget."
```

✅ **Express appreciation** frequently
```
"Thanks so much for explaining that!"
"I really appreciate you taking the time."
```

✅ **Admit when you don't know something**
```
"I'm not familiar with that yet. Could you point me to some documentation?"
```

---

**DON'Ts:**

❌ **Pretend to know what you don't know**
```
Bad: "Oh yes, I know that" [but you don't]
Good: "I haven't worked with that before, but I'm eager to learn."
```

❌ **Be too quiet** (people might think you're not engaged)
```
Bad: [Silent in all meetings]
Good: Ask at least one question per meeting
```

❌ **Overwhelm with questions** (but asking is good!)
```
Bad: "I have 20 questions right now!"
Good: "I have a few questions – when would be a good time to go over them?"
```

❌ **Criticize current processes** (too early!)
```
Bad: "Why do you do it this way? At my old company we did it better..."
Good: "Interesting approach! I'm curious about the reasoning behind this."
```

---

#### Slack/Teams Etiquette:

**Channel Posting:**

✅ Good first messages:
```
"Hi everyone! I'm Oleksandr, just joined the backend team today. 
Looking forward to working with you all! 👋"

"Good morning team! Quick question about the deployment process – 
is there documentation I should review?"
```

❌ Avoid:
```
"hi" [just "hi" with nothing else – people don't know how to respond]
"URGENT!!!" [on your first day, probably not actually urgent]
```

---

**DM Etiquette:**

✅ Good opening:
```
"Hi Kate! Hope I'm not bothering you. I have a quick question about 
the API authentication. Do you have a moment?"
```

❌ Avoid:
```
"Hi" [and then waiting for response before asking question]
"Can I ask you something?" [just ask!]
```

---

#### Meeting Etiquette:

**First Week in Meetings:**

✅ **Do introduce yourself** if you haven't met everyone
```
"Hi, I don't think we've met yet – I'm Oleksandr, I just joined the backend team."
```

✅ **Do take notes** visibly (shows you're engaged)

✅ **Do ask clarifying questions**
```
"Sorry, could you clarify what you mean by...?"
```

✅ **Do offer help** if appropriate
```
"I'd be happy to help with that if you need an extra pair of hands."
```

❌ **Don't dominate** the conversation

❌ **Don't multitask** obviously (especially on video calls)

❌ **Don't criticize** ideas in your first week
